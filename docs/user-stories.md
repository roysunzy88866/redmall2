## Gherkin 中文版语法(快速上手)

```gherkin
Feature: <故事名>

  Scenario: <场景名>
    假设 <前置条件>
    并且 <更多前置>
    当   <用户动作>
    则   <预期结果>
    并且 <更多结果>
```

关键字对应:
- `Given` = `假设`
- `And`(前置)= `并且`
- `When` = `当`
- `Then` = `则`
- `But` = `但是`

参考:https://cucumber.io/docs/gherkin/reference/

### US-CAR-01 · 推荐页幻灯 Banner

```gherkin
Feature: 推荐页顶部幻灯大图

  Scenario: 进入推荐页看到幻灯大图
    假设 后台推荐位已配置 4 张推荐图
    当   用户打开 APP 进入推荐页
    则   顶部显示单张大图,下方有 4 个圆点指示当前为第 1 张

  Scenario: 幻灯每 3 秒自动切换
    假设 用户停留在推荐页且未手动操作
    当   3 秒过去
    则   大图自动切到下一张,圆点指示同步前移

  Scenario: 手动滑动后静默 8 秒
    假设 用户在推荐页手动左滑了一张
    当   滑动完成
    则   接下来 8 秒内不自动切换,8 秒后恢复自动播放

  Scenario: 推荐位为空时不崩溃
    假设 后台未配置任何推荐图
    当   用户进入推荐页
    则   顶部幻灯区不显示或显示占位,页面其余部分正常,不报错

  Scenario: 只有 1 张推荐图时不轮播
    假设 后台只配置了 1 张推荐图
    当   用户进入推荐页
    则   顶部显示该张大图,不自动切换,圆点指示只 1 个(或不显示)
```

### US-CAR-02 · 推荐页「为你推荐」+ 左侧导航

```gherkin
Feature: 推荐页商品网格与左侧常驻导航

  Scenario: 左侧导航常驻显示全部入口
    当   用户在任意车机端页面
    则   左侧始终显示导航:推荐 / 车载用品 / 加油充电 / 户外旅行 / 3C数码 / 品质生活 /(最底)订单

  Scenario: 为你推荐取全部商品(后端供数)
    假设 商品库共有 12 个商品
    当   用户在推荐页向下滚动
    则   「为你推荐」网格展示全部商品(随机或按上架序),每行 2 个,每个含图片、名称、价格

  Scenario: 商品库为空时为你推荐显示空态
    假设 商品库一个商品都没有
    当   用户进入推荐页
    则   「为你推荐」区显示空态「暂无商品」,不报错

  Scenario: 点推荐商品进详情
    假设 推荐页显示「车载充电头 ¥39.00」
    当   用户点击该商品卡片
    则   进入「车载充电头」的商品详情页
```

### US-CAR-03 · 分类商品浏览

```gherkin
Feature: 点左侧分类浏览该类商品

  Scenario: 点分类显示该类商品网格
    假设 「车载用品」分类下有 6 个商品
    当   用户点击左侧导航「车载用品」
    则   右侧显示该类 6 个商品,每行 2 个,该导航项高亮为选中态

  Scenario: 切换分类右侧内容更新
    假设 用户正在看「车载用品」
    当   用户点击「3C数码」
    则   右侧内容切换为「3C数码」类商品,无独立分类页跳转

  Scenario: 空分类友好提示
    假设 「户外旅行」分类下暂无商品
    当   用户点击「户外旅行」
    则   右侧显示「该分类暂无商品」,不报错
```

### US-CAR-04 · 商品详情页 + 下单入口

```gherkin
Feature: 商品详情页展示与进入下单

  Scenario: 详情页展示完整信息
    假设 用户点开「车载充电头 65W 快充 ¥39.00」
    当   详情页加载完成
    则   显示 商品名称、价格、固定信息(7天无理由·包邮·自营)、描述、「下单」按钮

  Scenario: 多图商品的缩略图切换
    假设 该商品配有 3 张图
    当   用户点击第 2 张缩略图
    则   左侧主图切换为第 2 张图

  Scenario: 图片不足 3 张时自适应显示
    假设 该商品只配了 1 张图
    当   用户进入详情页
    则   只显示 1 张图、无空缩略图占位,不报错

  Scenario: 点下单进确认订单页
    假设 用户在「车载充电头」详情页
    当   用户点击「下单」
    则   进入确认订单页

  Scenario: 返回上一页
    当   用户在详情页点击「‹ 返回」
    则   回到进入详情前的页面(推荐页或分类页)
```

### US-CAR-05 · 确认下单 + 二维码支付

> 📌 设备 ID:车机端无登录,订单的「设备 ID」用**虚拟生成的 ID**(2026-05-29 确认,见共识 §4 B3 / A9)。

```gherkin
Feature: 确认订单到二维码假支付

  Scenario: 确认页展示固定假收货信息与订单详情
    假设 用户从「车载充电头 ¥39.00」详情点了「下单」
    当   确认订单页加载完成
    则   显示固定假收货信息(张三 138****8888 上海市…,只展示不录入)、订单详情(商品 ¥39.00 ×1,合计 ¥39.00)、「去支付 ¥39.00」按钮

  Scenario: 点去支付弹全屏二维码加倒计时
    假设 用户在确认订单页
    当   用户点击「去支付」
    则   弹出全屏二维码,显示「请扫码支付 ¥39.00」和从 02:59 开始的倒计时(179 秒,UI 显示惯例,见 [ADR-0004 §设计稿对照表](adr/0004-car-ui-ia-redesign.md)),以及「点击屏幕任意位置 = 支付成功」提示

  Scenario: 点屏任意处支付成功并回推荐页
    假设 二维码页正在显示,倒计时未归零
    当   用户点击屏幕任意位置
    则   显示「✓ 支付成功」,1.5 秒后自动返回推荐页,并生成一笔订单

  Scenario: 支付成功后后端落库订单(含价格快照与虚拟设备 ID)
    假设 用户对「车载充电头 ¥39.00」点屏支付成功
    则   后端生成一笔订单,固化 下单价 ¥39.00 / 商品名 / 数量,并写入服务端生成的虚拟设备 ID
    并且 该订单可被后台订单页查询到(US-ADMIN-06)

  Scenario: 进确认页后商品改价不影响本单价格
    假设 用户对「车载充电头 ¥39.00」点了「下单」进入确认页
    并且 此时管理员把该商品改价为 ¥49.00
    当   用户在确认页点「去支付」并支付成功
    则   该订单价格仍为 ¥39.00(进确认页那刻锁定的快照)

  Scenario: 支付瞬间订单写入失败则不算成功
    假设 用户在二维码页点屏,但此刻网络中断 / 后端写入订单失败
    则   显示网络异常提示(不显示「支付成功」、不返回推荐页)
    并且 不产生订单

  Scenario: 倒计时归零提示超时但系统不处理
    假设 用户在二维码页停留至倒计时归零
    当   倒计时到 00:00
    则   弹「支付超时」提示,系统不自动取消也不跳转
    并且 用户此时点屏幕任意处仍可支付成功
```

### US-CAR-06 · 网络异常处理

```gherkin
Feature: 断网与超时的友好提示

  Scenario: 断网打开显示网络异常
    假设 车机端没有网络
    当   用户打开 APP 或加载商品数据
    则   显示全屏「网络异常,点击重试」,不崩溃

  Scenario: 恢复网络后重试成功
    假设 当前显示「网络异常,点击重试」且网络已恢复

    则   重新拉取数据并正常显示页面
```

### US-CAR-07 · 车机端订单历史

```gherkin
Feature: 本机订单历史查看

  Scenario: 下单成功后订单出现在订单页
    假设 用户刚完成一笔「车载充电头 ¥39.00」的支付
    当   用户点击左侧导航「订单」
    则   订单列表顶部出现该笔订单,含 下单时间、状态「已支付」、商品名、价格、数量、收货信息(固定假数据,与确认页一致)

  Scenario: 订单按时间倒序排列
    假设 本机有 14:32 和 11:08 两笔订单
    当   用户进入订单页
    则   14:32 的订单排在 11:08 之上

  Scenario: 订单显示下单时价格快照
    假设 用户以 ¥39.00 下单了「车载充电头」,之后管理员把该商品改价为 ¥49.00
    当   用户查看该笔历史订单
    则   订单仍显示 ¥39.00(下单时快照),不随现价变动

  Scenario: 无订单友好提示
    假设 本机从未下过单
    当   用户进入订单页
    则   显示「暂无订单」

  Scenario: 订单列表加载失败显示网络异常
    假设 车机端在打开订单页时网络中断
    当   用户进入订单页
    则   显示「网络异常,点击重试」,不崩溃
```

## 📋 场景写作要点

- **场景独立**:每个场景能独立跑通,不依赖前一场景的状态
- **一个场景一个核心断言**:`Then` 部分聚焦,不要塞 5 个独立检查
- **避免实现细节**:写「显示支付成功」不要写「调用 `toast.show()`」
- **数据具体**:用真实数字 / 名称("充电头 ¥39"而不是"商品 X")
- **覆盖正常 + 边界 + 异常**:每个故事至少 1 个 happy path + 1-2 个错误 / 边界 case

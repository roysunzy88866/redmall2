## 2026-05-29 · 设计稿核对发现 3 处与共识/Gherkin 的语义不一致

**触发**:用户交付 `design_handoff_ridemall_carstore/`(Claude Design 出的 hi-fi 稿),我做"对照 US-CAR-01~07 七个故事每个都有对应设计页"的核对,顺带按 ADR-0004 收口承诺核对 §3 锚点语义一致性。

**核对结论**:7 个故事 100% 有对应设计页(推荐/分类/详情/确认/扫码/成功/订单历史/网络异常,共 8 屏)。但发现以下不一致,**未做改动,等用户裁决**。

### D-001 🔴 支付超时态行为冲突(必须裁决)

- **共识 §1 车机端**(锚 F5):"倒计时归零:弹「支付超时」提示,**系统不处理**(不自动取消/跳转;点屏仍可成功)"
- **user-stories.md US-CAR-05** 最后一条 Scenario:"倒计时归零...弹「支付超时」提示...**用户此时点屏幕任意处仍可支付成功**"
- **设计稿 README §5 二维码支付 · 超时态**:"替换为—— amber 警告环 + 「支付超时」+「二维码已失效,**请重新发起支付**」+ 两个按钮:「重新支付」(重置倒计时)/「返回订单」(回确认订单页)"
- **冲突点**:设计稿把超时态从"系统不处理 / 点屏仍可成功"改为"二维码已失效 / 必须重新发起支付",改变了**业务行为**,不是单纯视觉决策

### D-002 🟡 推荐页 Banner 手动滑动后 8 秒静默 · 设计稿缺失

- **共识 §1 + 锚 F4/A6**:"幻灯 4 张,3 秒自动切,**手动滑后 8 秒静默**"
- **user-stories.md US-CAR-01** Scenario 3:"手动滑动后...接下来 8 秒内不自动切换,8 秒后恢复自动播放"
- **设计稿 README §1 推荐页 + Interactions**:只说"3 秒自动切换 + 圆点可点击跳转",**没提手动滑动**,也没提滑动后的 8 秒静默
- **可能解释**:设计稿用圆点点击代替了手动滑动(车机触屏环境下也合理);但 8 秒静默这一行为在设计稿中没体现,实现时按共识做即可,设计稿无视觉差异。**轻**,但需用户确认按共识做

### D-003 🟡 倒计时起步 02:59 vs 03:00

- **共识 §1 + 锚 F5**:"3 分钟倒计时"
- **user-stories.md US-CAR-05** Scenario 2:"从 **03:00** 开始的倒计时"
- **设计稿 README + data 默认值**:`payRemainSec` 初始 = **179 = 02:59**
- **差异**:1 秒,UI 显示惯例(显示即可看到读秒)vs Gherkin 字面;**最轻**,可任选一种,但要统一

### 用户裁决(2026-05-29)

1. **D-001 → A**:维持共识(超时态点屏仍可成功)。实现时**不实现**设计稿的"二维码已失效 + 重新支付/返回订单"两个按钮
2. **D-002 → 按共识做 8 秒静默**(无视觉差,设计稿按圆点跳转 + 手动滑后 8 秒静默二者并存)
3. **D-003 → 02:59 起步**(179 秒,UI 显示惯例)

### 落实

- ✅ `user-stories.md` US-CAR-05 Scenario 2:03:00 → 02:59
- ✅ `ADR-0004` 追加「设计稿对照表」小节,锁定 7 故事映射 + 3 处裁决 + 视觉决策 + 设计参考源边界
- ✅ 共识 §3 锚点 F4 / A6 / F5 措辞不动(语义未变)
- 状态:**closed (2026-05-29)**
